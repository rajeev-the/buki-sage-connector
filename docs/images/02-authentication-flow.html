Sage OAuth 2.0 & Token Lifecycle

Interactive authorization with PKCE/state verification, refresh token rotation, and proactive buffer renewal

PHASE 1 Interactive User Authorization (npm run sage:auth)
1
CLI Trigger
User runs npm run sage:auth. Generates cryptographic state parameter.
➔
2
Callback Listener
Spawns local server on localhost:3000/api/sage/callback
➔
3
Sage Consent Portal
Opens browser to Sage Central OAuth. User selects Business Tenant & approves scopes.
➔
4
Exchange & Save
Validates state, POSTs code to Sage token API. Writes tokens atomically to .data/sage-tokens.json (0600).
PHASE 2 Autonomous Runtime Token Lifecycle & In-Flight Lock
A
Pre-Flight Check
Before any API call, evaluates expiresAt against a 60-second proactive buffer.
➔
B
In-Flight Lock
Single in-flight Promise mutex prevents concurrent requests from double-refreshing.
➔
C
Token Rotation
Exchanges current refresh_token for new access_token + new rotated refresh token.
➔
D
401 Auto-Recovery
If transient 401 occurs, triggers one immediate token invalidation & retry before failing.
Atomic File Storage (0600)
Tokens are written to temporary files and atomically renamed with POSIX 0o600 permissions, ensuring zero credentials leak to other processes.
Cloud / CI Auto-Seeding
In cloud environments (e.g. Render/Docker), seeds automatically from SAGE_ACCESS_TOKEN and SAGE_REFRESH_TOKEN env vars without manual browser flow.
Absent-Not-Default Rule
Business ID and tokens strictly validated. Corrupt or partial token payloads rejected upfront with explicit actionable CLI errors.
